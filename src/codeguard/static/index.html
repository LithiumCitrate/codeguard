METHOD AND LIMITS

方法与边界

CodeGuard 只回答一个问题：这段代码与本地语料里的哪些原文相似，按声明许可证要承担什么义务。

四阶段审查

  1. 多层指纹检索

    字面、局部别名、角色与结构边四层视图；默认用角色、抽象与结构边做 LSH 候选检索，验证时计算四层相似度。

  2. 回读原文，精确验证

    Jaccard、IDF 加权包含度与最长逐字 token 命中共同构成证据，原文只读回本机语料。

  3. 轻量模型判定

    12 维特征逻辑回归辅助判断片段来源。评分是模型输出，不应解释为经过校准的来源概率。

  4. 义务推理与门禁

    结合声明的许可证与使用方式给出工程风险；证据不足时降级为复核提示，而不是直接阻断。

适用边界

检测的是与本地语料的相似关系，不能证明大模型训练来源，也不能自动裁定侵权。未发现命中代表当前索引内没有足够证据，不能视为所有开源代码都已排查。演示案例由已知开源来源复制或改名生成，用于验证抗改写能力，不能代替真实 AI 生成样本评测。

自研程序以 Apache-2.0 开放；第三方语料保留原许可，按资源清单与下载脚本复现。语料版本已锁定，索引与判定权重随发布包一同提供。

大模型增强（可选）

风险分级、证据评分与许可冲突判定始终由本机确定性算法给出，断网也完全可用。大模型只在显式配置后作为解读层参与：文件速读、审查执行摘要、基于证据摘要的追问与许可条款通俗解释。每次调用的模型与用途写入报告的 ai_usage 字段；密钥仅保存在本机工作目录，不出现在任何导出物中。

本机离线 │ 不执行提交代码 │ 工程风险提示，不构成法律意见 CodeGuard / Review Workbench

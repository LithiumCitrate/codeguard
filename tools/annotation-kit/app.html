A/B/C 口径

A · 实质逐字复现连续、非平凡的一段实现被复制；通常 ≥20 token，或 ≥10 token 且覆盖率较高。改名、改格式、插注释不影响 A。
B · 惯用写法/公共片段只共享 imports、argparse、异常处理、常量表、短签名、文档字符串、常见数学/IO 写法；没有实质表达被复制。
C · 无法判断片段太短、原文太通用、回答是残片、边界需要第三人复核。拿不准就填 C，不丢人。

最容易误判的三种情况

  1. 跨项目副本：CodeGuard 命中了另一个仓库里的同一份上游代码。你仍然比较“GPT-4o 回答”和“论文配对原文”；如果确实复现，判 A，并在理由里写“命中为同源副本”。
  2. 注释/文档字符串：只复制注释或 docstring，通常判 B；注释和实现成段一起复制，按实现判 A。
  3. 短片段：只有 1–2 行通用表达式，判 B 或 C；不要因为系统给了 S1/S2 就判 A。

标注流程

  1. 在“开始”页选择“标注人1”或“标注人2”。
  2. 逐条看左右两段代码，用键盘 A/B/C 点判定；B/C 写一句理由。
  3. 进度自动保存。做完 47 条后点“导出我的 CSV”。
  4. 把 CSV 发给队长；不要转发 annotate.html，因为它含第三方原文。

试用反馈流程

  1. 把 trial/ 里的两份空白表给两位非项目成员。
  2. 他们本人填写任务完成情况、卡点原话、开放问题和签名。
  3. 回收后，在“试用汇总”页把关键信息照抄进来，生成汇总 Markdown。
  4. 队长把汇总和原始表一起放进参赛佐证。

常见问题

我能不能先全选 A，再慢慢看？ 不能。这样就不是独立标注了。每条必须看左右对照后再点。

我能不能看队友的 CSV？ 不能。两份 CSV 必须是各自完成的。

浏览器提示无法保存？ 用 Edge 或 Chrome，双击 start.bat 或把 annotate.html 拖进浏览器；每完成 10 条导出一次 CSV。

47 条太多？ 可以分两次做，进度会保存；但导出前必须 47/47。

# CodeGuard 设计说明

面向评审与二次开发者：这里写清楚**每个设计选择换来了什么、放弃了什么**，
以及为什么这些数字可以被逐字节复现。用法请看 [TUTORIAL.md](TUTORIAL.md)，
实验数据见 [BENCHMARK.md](BENCHMARK.md)。

---

## 1. 目标与非目标

目标：给定一段（很可能是模型生成的）代码，回答**它来自哪个项目的哪个文件、
该文件是什么许可证、这份许可证的义务能否进入当前产品的发布方式**，并给出
可人工复核的证据链和 CI 可消费的退出码。

非目标：不做风格/静态缺陷检查；不做"是否抄袭"的法律认定（这是工程风险提示）；
不做全仓依赖审计（那是 SCA 工具的职责，CodeGuard 输出的是 SCA 看不见的
**内联复制**）。

## 2. 为什么是零依赖、零大模型

| 约束 | 后果 |
|---|---|
| 评审必须能复现每一个数字 | 所有随机过程都用固定 seed；哈希用 blake2b 而非 `hash()`（后者有进程随机化） |
| 赛题明确不以参数规模/算力/成本评分 | 判定层用 12 维线性模型，训练 <1 s，权重可打印、可手算复核 |
| 合规报告本身不得引入第三方资源 | HTML 报告不引外链、不引字体、不引 JS；LLM 只在显式配置时启用，且**不参与**风险定级 |
| 无 GPU / 无 API Key 也要能跑 | 纯标准库实现，`pip install .` 不联网 |

## 3. 四层不变性视图

一个文件先经 `tokenize`（失败则退回首写迷你词法器，见 `normalize._fallback_tokens`），
得到带行号的代码 token 流（注释与文档串一律丢弃）。之后**滑动窗口**（window=48,
stride=24），每个窗口产出四个视图：

| 层 | 构造 | 对什么不变 | 会因什么失效 |
|---|---|---|---|
| L1 literal | 代码 token 原序列 6-gram | 空白、注释、格式化 | 改名 |
| L2 abstract | 窗口内按**首次出现顺序**把局部标识符替换为 `v0,v1,…`，数字/字符串按量级分桶，5-gram | 局部改名、常量微调 | 出现顺序变化、跨文件改名 |
| L3 role | 标识符归约为 `K:`(keyword)/`B:`(builtin)/`L`(local)/`A`(attr)，5-gram | 跨文件批量改名 | 大量插入新变量 |
| L4 edges | 从角色流抽取 定义形参/调用实参/绑定 关系边，**无序集合** | 语句与顶层定义重排 | 结构性重写 |

两个关键取舍：

- **别名表按窗口建立，不按文件建立**。全文别名化会被"在文件前部插入死代码"
  整体打乱（别名编号全部右移），窗口内别名化把破坏半径限制在一个窗口，
  这正是 `dead_code` 与 `compound` 变异仍然能被抓住的原因。
- **L4 用集合而非序列**。语句重排后 n-gram 序列面目全非，但
  `call.head|foo` / `bind|x|y` 这类关系边几乎不变；代价是丢失顺序信息，
  所以 L4 只作为多层之一，不单独作结论。

## 4. 检索：MinHash + b-bit + 分带 LSH

- **MinHash**：用 Mersenne 素数 2^61−1 上的成对独立置换 `(a·x+b) mod p`，
  置换系数由 seed 经 blake2b 派生，因此草图与运行环境无关。层尺寸
  role/abs=64、edge/lit=32。
- **b-bit 压缩**：每个最小值只存低 8 位用于桶定位，检索召回足够；
  估算阶段再用 `correct_bbit()` 扣除 1/256 的假同意偏差：
  `(agreement − 1/256) / (1 − 1/256)`。索引里因此只留 1 字节/维的签名摘要。
- **分带**：`BAND_PLAN = role 12 / abs 12 / edge 6 / lit 4`。带数越多、每带行数越少，
  S 曲线越靠左（召回高、假阳性多）。role/abs 是主力召回层，给 12 带；
  edge 与 lit 主要提供"确认可见性"，给 6/4 带。假阳性交给第二阶段消化。
  band key 截断到 uint32 存储，理论碰撞在 10^5 量级桶下对召回影响可忽略。
- **IDF**：`CountMin(4×2^16)` 记录每个 shingle 在语料中出现的 chunk 数，
  验证时按 `idf` 加权包含度。`call.arity|1`、`bind|L|L` 这类结构边在每个 Python
  文件里都有，不加权就会把两个无关文件判成相似——这是设计动机。
  **实测边界（一次真实修正的记录）**：我们最初在跨包抽查里测不到 IDF 的任何差异——
  原因不是 IDF 无用，而是索引容器没有持久化 `CountMin.total`，加载后所有权退化为
  常数 `log2`，即 IDF 在生产路径上一直是惰性的，而基准用的是内存中的新索引
  （同一个特征两套取值 = train/serve skew）。修复并给容器升版本后：
  200 个真实文件的跨包命中从 83 降到 79，`benchmark` 的"阈值敏感性"表才给出
  逐阈值的假对抑制（0.55 约 +0.9%，0.25 约 +3.7%）。
  结论：IDF 买到的是**允许调低阈值追更高召回而不失控的余量**，不是文件级检出率——
  出厂阈值下的检出率并不依赖它，我们照实这么写。

## 5. 两阶段：便宜召回，昂贵确认

第一阶段只做桶查询（毫秒级）。第二阶段只对被召回的 `top_verify=4` 个候选执行：
回读语料原文 → 取与候选行区间重叠的窗口并集 → 计算四层**精确 Jaccard**、
IDF 加权包含度、**最长逐字 token 连续命中**（对 n-gram 做二分，`evidence.longest_common_run`）。
这样既避免全局 O(N²) 比较，又保证最终报告里的每个数字都是精确值而非草图估计。
"最长逐字命中 46 个 token"这种证据，是法务和工程师都能直观理解的。

## 6. 打分与聚合

12 维特征（见 `score.FEATURE_NAMES`）→ 逻辑回归（SGD + L2，400 epoch，
seed 20260101）。三处刻意设计：

- **按来源文件分组留出**（`score.group_split`）：同一文件的近似重复片段若同时
  出现在训练与测试集，AUC 会虚高；留出单位是整个来源文件。
- **Youden's J 选阈值**：门禁要的是"漏报与误报之和最小"，而不是固定 0.5。
- **无模型时规则回退**：`0.45·wc + 0.25·max_sim + 0.2·verbatim + 0.1·band_hits`，
  与模型权重方向一致，保证工具在刚建好索引、还没跑基准时也能用。

片段 → 文件聚合：`confidence = min(1, 0.65·peak + 0.35·min(1, 3·coverage))`。
峰值概率说明"确实有这么一段"，覆盖率说明"不是一个巧合片段"；3 倍斜率让
覆盖 1/3 以上片段的文件就能封顶，符合"整份文件被改写"的真实形态。

## 7. 许可证推理：义务模型而非查找表

每种许可证是一个 `LicenseProfile`：`family / scope / notice / source_offer /
same_license / weaker_ok / network_trigger / state_changes / relink / clauses`。
判定 = 在该使用方式下测试义务能否被满足：

1. `_triggers()` 先判使用方式是否触发实质条件（纯内部使用 → 只有保留声明）。
2. `strong/network` 走 `compare(required_license(src), tgt)`，返回 `ok/upgrade/fail`
   三态：`upgrade` → conditional 并把"整件作品须按 X 授权"写成**义务**而非注释。
3. 弱 copyleft 按 scope 分支：library 要求可重链接，module 要求被改文件保持原证，
   file 只约束该文件本身。
4. `CONFLICTS` 只保留**无法从义务缺失推出、源于条款相互冲突**的组合
   （Apache-2.0 专利终止条款 vs GPLv2 §6；BSD-4-Clause 广告条款；GPL-2.0-only vs
   GPL-3.0-only 互不可升级）。AGPL→GPL 曾经也写死在表里，现在由 `compare()` 推导。
5. `AGPL §13` 独立于分发条件：即便源/目标同为 AGPL 且"分发"成立，
   网络服务场景仍强制追加 §13 义务并降级为 conditional（S3），
   因为"内部部署不豁免"正是这类污染最常被忽视的地方。
6. 解析链 PEP639 → `license` → trove → 源码头部 → `UNKNOWN`；
   `UNKNOWN` 一律 `unknown`（S2）而不是放行。

风险分级 `S0…S4` 由 `(status, confidence, usage)` 决定，并且**必须有佐证才允许阻断**：
`corroborates()` 要求「≥2 片段、覆盖率 ≥0.15 且逐字命中 ≥10 token」或
「逐字命中 ≥20 token」或「整体置信度 ≥0.75」，否则 S3/S4 一律降为 S2 提示。理由来自实测：
在 200 个互不相关的真实语料文件上跑产品原路径（被扫描项目许可证按最坏的
`LicenseRef-Proprietary` 假设），无佐证的孤立片段造成 3.5% 的文件被误阻断；加上佐证与
"置信度参与定级"之后为 0%，而 192 个变异用例的阻断召回仍接近检出率本身
（见 `codeguard benchmark --fp-study 200`）。真实仓库回归又发现了纯 CLI 样板造成的
6 片段 / 22% 覆盖率 / 5 token 逐字命中，因此结构分支增加 10 token 下限，置信度门槛
从 0.65 提到 0.75；该案例现在降为 S2，不再误阻断。
同一理由适用于 `risk_level()`：0.5 概率的冲突是"复核项"，不是"构建失败"。

## 8. 输出与集成

- `codeguard.provenance/v1`：subject / source / verdict / 逐片段 evidence（行号、
  概率、逐字命中、四层 Jaccard、12 维特征）+ disclaimer。
- CycloneDX 1.6：`components[].evidence.occurrences` 带 `文件#行区间`，
  让内联复制出现在 SBOM 里——传统 SCA 只能记录依赖包。
- 自包含 HTML：给非技术干系人看，无外部资源。
- SARIF 2.1.0：`scan --format sarif` / `gate --sarif`，规则 `CG001–CG004`，供 GitHub Code Scanning 与 IDE 消费。
- CI：`gate` 只看 diff 新增行（`strip_diff_markers`），退出码 0/1/2 是公开契约。
- 外部评测：`eval` 读取 JSONL 清单，统计干净样本误阻断与复制样本归因，并给出单侧 Clopper-Pearson 上限；
  报告不写入样本源码，HumanEval 仅作为外部干净负例（`docs/EVALUATION.md`）。

## 9. 复杂度与容量

语料 N 个文件、平均 T token：建索引 O(N·T)，磁盘 ≈ 328 B/窗口 + 压缩后的 CMS。
实测 585 文件 → 36 193 窗口 → 8.9 MB，加载 0.57 s。查询 M 个窗口：
LSH 阶段 O(M·Σ带内命中)，验证阶段 O(M·top_verify)。实测 1.6 k 字符的改写样本
0.65 s（41 对候选精确验证），49 k 字符 / 1390 行的真实文件 3.9 s（665 对验证）。
索引增长是线性的，没有全量两两比较的平方项。

## 10. 隐私与许可证边界（本项目自身）

- 索引不含源码原文，只有哈希与行号；精确验证回读**本地**语料。
- 语料（含 GPL/LGPL 包）由使用者在**审查环境**本地下载，
  不随仓库分发，也不与产品代码链接——这是"只读检测样本"，不是衍生作品。
- CodeGuard 自身代码为 Apache-2.0，全部为自研；第三方仅有 SPDX 许可证清单（CC0）
  与 Python 标准库，逐项列在 `THIRD_PARTY_NOTICES.md`。
- `src/codeguard/data/negatives/` 的 9 个"干净实现"是自研基准负例，
  既做精确率负例，也做测试 fixture，避免引入外部数据集。

## 11. 已知局限（不粉饰）

| 局限 | 现状 | 影响 |
|---|---|---|
| `partial`（只截取部分定义）检出率 92%，低于其它 7 类 | 截断后窗口数量少、覆盖率天然低 | 报告用 `coverage` 显式暴露，靠人工确认残余 8% |
| 跨语言移植（同一算法 Python→Java）| 词法与角色流都不同，不可见；非 Python 文件仍可安全扫描（走通用词法器，实测不崩、不误报），但缺少语言专用角色层，改写后召回无保证 | 明确划为非目标；v0.3 计划为每种语言实现同样的四层视图 |
| 极短片段（<10 token）不建窗口 | 设计上排除，否则噪声压倒信号 | 短函数赋值本就不构成实质性复制 |
| 语料未覆盖的项目 | 无法归因到具体文件 | 只能给出"结构相似"证据，需人工判断 |
| 许可证文本变更（自创许可证） | 落到 `UNKNOWN` → S2 阻断人工确认 | 保守但正确：不默认放行 |
| 混淆式重写（控制流平坦化、算法等价替换） | 指纹会失效 | 属于抄袭检测的开放问题，不在门禁保证范围 |

## 12. 扩展点

- 新许可证：只需加一个 `LicenseProfile`，无需扩大冲突表。
- 新语言：实现 `role_stream/tokenize` 的语言分支，四层与检索层不变。
- 新打分器：只要输出 12 维特征的 `probability()`，规则/模型/未来的排序器可替换。
- 新评测集：`evaluate.load_manifest()` 接受 JSONL；`clean`/`copied` 与 `source_package` 即可接入，
  不需要改扫描核心。
- 外部大模型：`llm.get_provider()` 增加一个 provider，结论与风险等级仍由算法决定。
